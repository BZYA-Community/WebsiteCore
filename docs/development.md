# Development Guide

How to set up a working environment, how the codebase is organized, and how to make changes safely. Read [../CONTRIBUTING.md](../CONTRIBUTING.md) for the PR process and the mandatory BVT checks before submitting anything.

## Toolchain

| Tool | Version | Used for |
| --- | --- | --- |
| Go | see `go.mod` (1.24+) | backend |
| Node.js | 22.x (CI parity); 20.19+ works | frontend |
| npm or Yarn 1.x | — | frontend deps; `make build-web` uses Yarn, CI uses npm |
| Docker + Compose | recent | PostgreSQL / Redis / Meilisearch dev stack |
| GNU make | — | task runner |
| gofumpt, go-enum | latest | formatting and codegen (`make install-tools`) |
| golangci-lint | v1.64.8 (CI parity) | Go linting |
| Python 3 + Playwright | recent | frontend verification scripts under `scripts/` |

First-time setup:

```sh
make install-tools          # gofumpt + go-enum
make deps-up                # dependency stack (Docker)
cp config.yaml.sample config.yaml
# set JWT.Secret (openssl rand -hex 24)
make migrate                # create schema
make build-web              # build frontend into web/dist/
make run TAGS='embed'       # http://127.0.0.1:8008
```

Details and troubleshooting: [deploy/local.md](deploy/local.md).

## Repository layout

```text
├── auto/        # GENERATED by go-mir — never edit by hand
├── cmd/         # CLI entrypoints: serve, migrate, version
├── internal/
│   ├── conf/        # config loading (embedded defaults + external yaml)
│   ├── core/        # service interfaces + domain types (the contract layer)
│   ├── dao/         # data access: db, redis, search, storage, security(SMS)
│   ├── servants/    # HTTP/gRPC handlers implementing the generated interfaces
│   ├── service/     # feature-driven assembly of sub-services
│   ├── sitesetting/ # admin-UI-managed settings (registry, encryption, bootstrap)
│   └── infra/       # infrastructure (migration runner, etc.)
├── mirc/        # API definitions (the single source of truth for routes)
├── pkg/         # shared utilities (app, json, xerror, version, ...)
├── scripts/     # migrations, E2E/verification scripts, systemd/launchd units
└── web/         # Vue 3 SPA (see web/README.md)
```

The layering rule: `servants` implement interfaces generated from `mirc` definitions, call `core` service interfaces, which are implemented over `dao`. New behavior flows mirc → generate → servants → service/dao.

## Backend tasks

```sh
make run TAGS='embed'   # run API + embedded frontend
make run                # run API only
make build              # binary to release/paopao
make test               # go test ./...
make fmt                # gofumpt
make vet                # go vet (internal + pkg)
make migrate            # apply DB migrations (adds the migration tag for you)
make deps-up|down|logs|status|reset   # dependency stack
```

Build tags: `embed` (serve the compiled SPA from the binary), `migration` (include the migration engine), `docs` (OpenAPI docs service on :8011). Combine as needed: `make run TAGS='embed migration'`.

### Adding or changing an API

1. Declare the endpoint in `mirc/web/v1/` (or `mirc/admin/`, ... — see [../mirc/README.md](../mirc/README.md) for the service table).
2. Regenerate: `make gen-mir` (runs `go generate mirc/gen.go`, writes `auto/api/...`, then gofumpt). Never hand-edit `auto/`.
3. Implement the handler in `internal/servants/web/` (or the matching service).
4. If persistence changes are needed, add a migration pair to **both** `scripts/migration/postgres/` and `scripts/migration/mysql/` (see [deploy/database.md](deploy/database.md)).
5. If you touched configuration, update `internal/conf/config.yaml` (embedded) **and** `config.yaml.sample` in the same PR.

### Enum codegen

```sh
make gen-enum    # go generate ./internal/model/enum/...
```

## Frontend tasks

```sh
cd web
npm install
npm run dev        # Vite dev server
npm run lint       # ESLint
npm run lint:fix
npm run format     # Biome (formatting only)
npm run build      # production bundle to web/dist/
```

Division of labor: **Biome** owns formatting (indent, quotes, import order); **ESLint** owns code quality (vue flat/strongly-recommended + typescript-eslint recommended). Both must pass; CI runs ESLint and the Vite build.

The API base URL comes from `VITE_HOST` (`web/src/utils/request.ts`). It is empty by default, meaning same-origin requests — correct for the embedded production build. For standalone `npm run dev`, create `web/.env.local`:

```text
VITE_HOST="http://127.0.0.1:8008"
```

and run the backend (`make run`) alongside the Vite dev server.

Frontend feature flags (`VITE_ALLOW_*`, `VITE_DEFAULT_*` in `web/.env`) mirror the backend `WebProfile` settings; when `VITE_USE_WEB_PROFILE=true` the values are fetched from the backend at runtime, so the admin UI is authoritative.

## Testing

### Unit tests

```sh
make test        # or: go test ./...
```

### End-to-end and verification scripts (`scripts/`)

These hit a running local instance (default `http://127.0.0.1:8008`) and/or drive a headless browser with Playwright. Install prerequisites with `pip install playwright requests && playwright install chromium` (check each script header for exact needs and seeded accounts).

| Script | What it verifies |
| --- | --- |
| `test_audit_flow.py` | Comment / reply / nickname moderation flow end to end (API level) |
| `test_course_flow.py` | Course module flows (two-phase; needs `daoyou1`/`daoyou2`/`testaudit` accounts) |
| `test_whisper_matrix.py` | Private-message permission matrix (phone binding required, peer-to-peer rules, first-message limits) |
| `verify_sidebar_830.py` | No sidebar/content overlap at the 830px viewport breakpoint |
| `measure_width.py` | Column layout at 7 viewports: 1920 / 1600 / 1366 / 1200 / 1000 / 821 / 375 |
| `screenshot.py`, `screenshots_audit.py` | Page screenshots for manual visual comparison |

Run the ones relevant to your change and paste the summary lines into the PR (the PR template has a section for this). The **BVT** — the mandatory minimum for every PR — is defined in [../CONTRIBUTING.md](../CONTRIBUTING.md).

## Debugging and profiling

- `App.RunMode: debug` + `Logger.Level: debug` for verbose local output.
- `Pprof` feature → `http://127.0.0.1:6060/debug/pprof` (never expose publicly).
- `Metrics` feature → Prometheus endpoint on `:6080`.
- `Sentry` / `Pyroscope` features for error tracking and continuous profiling.
- `make run TAGS='docs'` → OpenAPI reference at `http://127.0.0.1:8011/docs/openapi`.
- Server logs: `LoggerFile` writes to `custom/data/.../logs`; dependency logs via `make deps-logs`.

## Commit conventions

Conventional prefixes, required (the weekly report classifies by them): `feat:` / `fix:` / `docs:` / `refactor:` / `chore:`. One PR does one thing and links its issue. Never commit secrets, tokens, or personal data — automated review rejects these outright.
