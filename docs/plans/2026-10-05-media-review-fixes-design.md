# PR #107 媒体上传审查修复

本次只处理课程临时对象保存、H.264 尺寸校验、转码输出超限三个问题，保留 #105 已确认的格式、尺寸、字节上限及本机验收约束。

## 课程临时对象

通过现有 `ObjectStorageService` 先执行 `PersistObject`，失败立即返回；成功后检查正式对象存在，再写课程记录。直接上传/无临时目录模式仍由存在性检查兜底。同一视频的课程编辑不重复转存。不要改变提供商接口或在业务代码里判断 AliOSS/LocalOSS。

回归覆盖新建、替换、已有正式对象、对象缺失、转存失败、存在性查询失败以及失败时不改数据库、不删旧视频。AliOSS 的真实测试 Bucket 仍由维护者验收，模拟存储不等同于提供商验收。

## H.264 尺寸

仅信任 `avc1` 元数据不能限制解码尺寸。新增有界的 SPS 位流读取，按 H.264 宏块、色度采样、逐行/隔行及裁剪字段计算实际尺寸；所有 SPS 均须符合 1080p 规则且与样本条目一致。按样本表流式读取视频 NAL 单元，防止样本中另带超限 SPS；拒绝不支持的扩展编码和损坏的长度/表结构。不引入生产 FFmpeg 或新依赖，不把视频整文件加载到内存。

回归使用 FFmpeg 生成独立 MP4：修改四字节容器宽高后仍须拒绝 1440p，正常横竖 1080p 保持可用；覆盖多 SPS、截断、裁剪、参数集替换和无效样本边界。

浏览器硬件编码器可在普通 AVC 切片前输出 type 14 前缀 NAL；它不定义图片尺寸，允许通过。定义尺寸的 SPS 仍需校验，type 20/21 扩展切片继续拒绝。该兼容性差异通过真实 WebCodecs 样本发现并加入回归测试。

## 转码输出上限

Mediabunny 的 `write` 事件是通知，抛异常不能取消任务。保留现有输出方式，在第一次超限通知中记录大小错误并调用 `Conversion.cancel()`，不再在通知回调中抛异常。统一让普通视频和课程视频尽早取消；错误处理优先呈现大小错误，释放转换及 OPFS 资源。用户主动取消仍沿用原有流程。

验证使用实际 Mediabunny 转换，确认输出超限时取消、拒绝后续处理且不完成整段；检查边界内正常输出和用户取消。完整构建、测试、lint 及相关本机接口验证完成后更新同一个 PR，旧 BVT 视频不作为新修复的通过证据。

执行前端回归：安装 FFmpeg 后运行 `cd web && npm run test:media`。四项测试使用真实 Mediabunny 转换，覆盖 BufferTarget/StreamTarget 超限取消、精确字节边界和主动取消；已接入 CI。浏览器补测通过本地诊断页调用同一生产构建的 `compressVideo`：26,799,473 字节 MP4 触及 30 MiB 输出上限，在 33% 进度停止并保留大小错误；正常 WebCodecs 视频上传成功。
